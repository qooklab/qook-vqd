# DART 수집 경로 점검 및 수정

## 범위와 확인 한계

DART 기업코드 ZIP/XML → 3개년 재무제표 → 점수 계산 → 캐시 → stock_latest 저장 → 화면 결과 표시를 점검했다. 작업 환경에는 DART·Supabase 키와 운영 로그가 없으므로, 실제 운영 실패의 외부 원인을 확정한 것은 아니다. 아래 결함은 기존 코드에서 테스트로 재현한 뒤 수정했다.

## 재현한 결함

1. **기업목록 실패가 후속 조회까지 막음.** 유효성 검사 전에 전역 map을 할당해, 목록 해석이 실패한 다음 요청에서는 빈 map을 그대로 재사용했다. 정상 해석·검증을 마친 map만 공개하도록 변경했다.
2. **XML 공백으로 기업코드 매칭 실패.** stock_code/corp_code 값 주위의 공백을 허용한다.
3. **점수가 없는 실패 결과를 7일간 재사용.** 모든 점수가 null인 캐시는 다시 조회하고, 새 미산정 결과는 저장하지 않는다. 처리 버전·평가 연도가 다른 기존 캐시도 재산정한다. 정상적인 0점은 계속 캐시할 수 있다.
4. **연결 자료만 조회.** 연결(CFS)에 자료 없음(013)이 발생하면 3개년 전체를 별도(OFS) 기준으로 다시 조회한다. 연도별 연결·별도 수치를 혼합하지 않는다. [공식 재무제표 가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020)는 두 재무제표 구분과 013 응답을 정의한다.
5. **계정명 공백과 빈 금액 처리.** 공백·전각 문자 차이를 정규화하되, 계정명은 지정한 항목에만 매칭한다. 빈 금액은 0이 아닌 미확인으로 처리하고, 괄호로 표시된 손실 금액은 음수로 읽는다.

## 관련 개선

- 전체 기업목록을 한 번 받으면 등록 종목 30개의 기업코드를 함께 캐시한다. 삼성전자우는 삼성전자 기업코드를 사용한다. 이후 함수 인스턴스에서도 종목마다 큰 ZIP을 다시 받을 필요를 줄인다. [공식 기업코드 가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019018)는 ZIP 내 8자리 기업코드와 6자리 종목코드를 구분한다.
- DART 인증키 미설정, 010/011 인증키 문제, 012 IP 제한, 020 한도 초과, 점검/서버 오류, 캐시 테이블 누락을 구분한다. 키·IP·한도 등 배치 공통 오류는 남은 종목 요청을 중단한다. 인증·한도 오류에 무작정 OFS 재조회나 자동 재시도를 하지 않는다.
- JSON 정상 상태여도 list가 없거나 형태가 잘못되면 명시적인 응답 형식 오류로 처리한다.
- 시세가 없는 종목은 DART 요청 전에 안내한다.
- 정상적인 최신 평가에서 더 이상 산정할 수 없는 항목은 과거 점수가 남지 않게 null로 갱신한다. 조회 자체가 실패한 경우에는 기존 점수를 덮어쓰지 않는다.
- 성공 결과에 조회 연도·연결/별도 기준을 표시한다. 금융업 재무 건전성 미평가는 기존 평가 정책임을 알린다.
- 이익 안정성·성장률·일반기업 부채비율의 배점 산식은 유지한다. KIS·인증 방식·디자인 구조는 변경하지 않는다.
