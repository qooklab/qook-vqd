# DART 재무평가 시간 초과 처리

증상: 기업은행의 '선택 종목 DART 재무평가'에서 `수집 실패: The operation was aborted due to timeout` 표시.

## 확인한 원인과 한계

기존 기업목록 요청은 12초, 연도별 재무제표 요청은 8초 후 중단했다. 기업목록의 중단은 원문 TimeoutError로 전달되었고, 연도별 중단은 재무점수 미산정(422)으로 변환되었다. 화면은 호출 제한만 재시도했기 때문에 일시적 시간 초과에서 회복하지 못했다. 보고된 정확한 외부 서비스 지연 원인은 API 키와 운영 로그가 없어 확정하지 않았다.

## 변경

- 기업목록 20초, 연도별 재무제표 12초. 응답 헤더뿐 아니라 본문을 읽는 동안에도 제한 적용.
- 실패 단계가 포함된 안전한 오류 메시지. 요청 URL·인증키는 오류 문구에 포함하지 않는다.
- 시간 초과를 `UPSTREAM_TIMEOUT`, `retryable: true`, HTTP 504로 전달. 연도별 일시 지연도 영구적인 '미산정'으로 취급하지 않는다.
- 화면은 시간 초과 때 2.5초·5초 후 최대 두 번 재시도한다(최초 포함 세 번). 기존 호출 제한의 최대 세 번 재시도는 유지한다. 재시도 상태를 진행 영역에 표시한다.
- 인증 실패·입력 오류·영구적 미산정은 자동 재시도하지 않는다. 반복 시간 초과 종목은 오류로 남기고 다음 선택 종목을 처리한다.
- 수동 갱신 함수 실행 한도를 30→60초로 조정해 기업목록·재무제표·저장의 순차 작업에 여유를 준다. [Vercel 함수 실행 시간 설정](https://vercel.com/docs/functions/configuring-functions/duration) 참고.
- 은행 업종의 점수 산식·7일 캐시·KIS 시세 수집·인증 방식은 유지한다.

## 검증

`node --test scripts/test-refresh-timeouts.cjs`: 12개 통과. 본문 중단, 단계명, 과거 502 오류와 게이트웨이 시간 초과 분류, 인증 보호, 연도별 오류 전달, 은행 점수 산식, 두 번 재시도 후 성공, 지속 실패의 세 번 제한을 외부 호출 없이 검증한다.

`npm run typecheck` 및 `npm run build` 통과. 실제 DART 요청과 운영 배포 상태는 미검증이다. 배포 반영 후 기업은행만 선택해 DART 재무평가를 재실행하고, 다시 실패하면 새로 표시되는 단계명을 기준으로 운영 로그와 함께 확인한다.
